# League Companion - Android

Клиент к бэкенду из `../backend`. Kotlin, Jetpack Compose, MVVM, Room, Retrofit, Hilt.

## Настройка перед первым запуском

`local.properties` не коммитится и создаётся вручную (Android Studio сама пропишет
туда `sdk.dir` при открытии проекта):

```properties
sdk.dir=C\:\\Users\\<имя>\\AppData\\Local\\Android\\Sdk
LC_BASE_URL=http://10.0.2.2:8080/
LC_API_KEY=<то же значение, что CLIENT_API_KEY в корневом .env>
```

Оба значения уезжают в `BuildConfig` (см. `app/build.gradle.kts`) - в коде их нет и
быть не должно. Если `local.properties` отсутствует, значения берутся из переменных
окружения с теми же именами, иначе - из дефолтов; так собирается CI.

`10.0.2.2` - адрес хост-машины **изнутри эмулятора**. `localhost` там означает сам
эмулятор, и запрос не дойдёт. Для устройства по USB нужен IP машины в локальной сети
и `adb reverse tcp:8080 tcp:8080`.

`LC_API_KEY` обязан совпадать с `CLIENT_API_KEY` бэкенда: несовпадение даёт `401`, и
экран честно скажет, что дело в ключе приложения, а не в саммонере.

## Сборка и проверки

```bash
./gradlew :app:assembleDebug
./gradlew :app:ktlintCheck      # ktlintFormat - автоисправление
./gradlew :app:testDebugUnitTest
./gradlew :app:lintDebug
```

Те же четыре команды гоняет CI (job `android` в `.github/workflows/ci.yml`).

### Если юнит-тесты падают с `Could not find or load main class`

Gradle подставляет `PATH` в `-Djava.library.path` тест-воркера. Одна запись `PATH` с
незакрытой двойной кавычкой ломает разбор командной строки Windows, и воркер падает
ещё до JUnit - при том что `assembleDebug` проходит. Лечится чисткой самой
переменной среды; разово помогает `set "PATH=%PATH:"=%"` перед вызовом `gradlew.bat`.

## Что где лежит

```
data/remote      Retrofit, DTO (зеркала backend/internal/httpapi/dto.go), разбор ошибок
data/local       Room: сущности - зеркала таблиц бэкенда, DAO, конвертеры, миграции
data/mapper      сеть → база → домен
data/repository  offline-first: чтение из Room, запись из сети
domain/model     модели для UI
ui/search        поиск по Riot ID и список уже отслеживаемых - стартовый экран
ui/summoner      профиль и лента матчей одним списком
ui/match         детали матча: обе команды, все десять участников
ui/stats         статистика за 30 дней, топ-5 чемпионов
ui/components    LoadingBox / ErrorState / EmptyState - три состояния из SPEC.md 4.4
ui/error         единственное место, где AppError превращается в текст
ui/image         ссылки на Data Dragon и картинка с заглушкой
di               Hilt: сеть, база, загрузчик картинок
```

Правило одно: **UI читает только из Room**, сеть пишет в Room. Поэтому офлайн
получается по построению, а не веткой `if` в экране, и провал обновления не стирает
уже показанное. Исключение ровно одно - статистика: её считает бэкенд, локальной
копии у неё нет, и офлайн этот экран честно показывает ошибку с повтором.

### Схема Room

Версия базы поднимается **миграцией**, а не `fallbackToDestructiveMigration`:
на устройстве лежат саммонеры, которых заводили руками, и терять их при обновлении
приложения нельзя. Destructive остаётся запасным путём на случай, когда миграции нет.
Схемы экспортируются в `app/schemas` - там видно, что менялось.

### Картинки

Иконки берутся с Data Dragon, версия CDN зафиксирована константой в
`ui/image/DataDragon.kt`. Выводить её из `gameVersion` матча можно, но у иконки
профиля матча нет вовсе, а квадратики чемпионов от патча к патчу не меняются. Старые
версии CDN не удаляются, поэтому константа не протухнет - она просто не будет знать
чемпионов, вышедших позже; промах даёт заглушку, а не ошибку экрана.

Загрузчик картинок собран на **отдельном** OkHttp-клиенте. Общий несёт
`ApiKeyInterceptor`, и переиспользование отправляло бы `X-API-Key` бэкенда на CDN Riot
при каждой иконке.

## Живая проверка

1. В корне репозитория: `docker compose up -d` (нужны `RIOT_API_KEY` и `CLIENT_API_KEY`
   в `.env`).
2. Запустить приложение на эмуляторе, ввести Riot ID целиком (`Name#TAG`), выбрать
   регион → **Find**. Экран профиля откроется сам.
3. Лента может быть пустой первые несколько секунд - это ожидаемое состояние:
   `POST /summoners` отвечает `201` до того, как синхронизация догрузит матчи.
   Потянуть вниз (pull-to-refresh), и матчи появятся.
4. Тап по карточке матча - детали, кнопка **Stats** в шапке профиля - статистика.
5. Офлайн: выключить сеть у эмулятора и перезапустить приложение - профиль, лента и
   уже открытые матчи остаются на месте, они читаются из Room.
