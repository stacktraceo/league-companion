# DECISIONS.md - League Companion

Технические решения проекта: то, что зафиксировано и не пересматривается по ходу
работы. `SPEC.md` - техническое задание и источник истины по функциональности;
секция «Отклонения от SPEC.md» ниже имеет приоритет над ним, если они расходятся.
Текущее состояние работ - в `PROGRESS.md`.

## Стек (зафиксировано)

- Backend: Go 1.22+, роутер - **chi**
- БД: PostgreSQL 16, миграции - golang-migrate
- Кэш: Redis (см. SPEC.md 3.1)
- Android: Kotlin, Jetpack Compose, MVVM, StateFlow, Room, Retrofit + OkHttp, Hilt

## Отклонения от SPEC.md

1. **Хранение матчей.** Помимо распарсенных полей в `match_participants`, в `matches`
   есть колонка `raw_data JSONB` - туда пишется полный JSON-ответ Match-V5 при первой
   синхронизации. Цель: расширение набора полей (предметы, руны, спеллы) в будущем не
   должно требовать повторных запросов к Riot - данные уже лежат локально.
2. **Идемпотентность.** Все `INSERT` в `matches` и `match_participants` - через
   `ON CONFLICT DO NOTHING`. Несколько отслеживаемых саммонеров могут встретиться в
   одном матче и синхронизироваться параллельно - гонка на `match_id` реальна.
3. **Auth Android↔Backend.** Shared-secret заголовок `X-API-Key`, проверяется
   middleware на всех `/api/v1/*`, кроме health-check. Значение - в `.env` бэкенда и
   в конфиге Android-клиента (BuildConfig, не хардкодить).
4. **Sync worker.** Guard от наложения синхронизаций - atomic bool `syncInProgress`;
   если предыдущий прогон тикера ещё не завершился, следующий тик пропускается с
   логом, а не встаёт в очередь.

## Конвенции

- Перед каждым коммитом: `gofmt -l .`, `go vet ./...`, `golangci-lint run` (backend);
  ktlint/Android lint (android). Ничего не коммитить, если эти проверки красные.
- TDD для трёх компонентов, явно требуемых в DoD: rate limiter, region routing
  mapping, агрегация статистики - сначала тест, потом реализация.
- Один коммит = одна логическая фича. Conventional Commits со scope:
  `type(scope): описание`, где `scope` - `backend` или `android`. Типы: `feat`, `fix`,
  `refactor`, `test`, `docs`, `chore`, `ci`.
- Секреты (`RIOT_API_KEY`, `X-API-Key`) - только через `.env` / переменные окружения.
  Никогда не коммитить, не печатать в логи, не подставлять в тестовые фикстуры как
  реальные значения.

## Процесс

Разработка идёт вехами из `SPEC.md`, раздел 5 («План разработки»), они же - секции в
`PROGRESS.md`. На каждую веху: реализация → прогон тестов → отметка выполненного в
`PROGRESS.md` (при необходимости - запись в «Журнал решений», если по ходу принято
архитектурное решение, не описанное здесь) → коммит.

Промежуточные коммиты и актуальный `PROGRESS.md` - единственный способ восстановить
контекст работы позже.

## Riot API

- Ключ протухает раз в 24 часа, обновляется вручную на developer.riotgames.com - это
  ожидаемое ограничение dev-ключа, а не то, что чинится кодом.
- Region routing (platform vs regional) - только через выделенную функцию маппинга с
  юнит-тестом, см. SPEC.md 3.2 и риски в SPEC.md 7.
